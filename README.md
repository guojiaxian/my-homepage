# my-homepage · 我的应用导航

部署在这台服务器上的个人应用展示主页：以**表格 / 卡片**两种视图列出**本机应用**、**局域网其他主机上的外机应用**与**云服务器上的公网应用**的名称、简介、**实际访问端口/地址**、部署位置与 GitHub 地址，支持**手动排序**（拖拽 / 上下移动）以及按名称 / 端口 / 运行状态 / 同步状态排序。端口与运行状态、**源码是否已同步至 GitHub** 由服务端定时探测：**端口/状态每 3 分钟、完整 git 同步每 5 分钟**，页面每 60 秒轮询刷新，应用换端口、上下线、源码有未提交/未推送改动都会自动反映到主页，无需改前端代码。

- 技术栈：Vue 3 + Vite（构建产物为纯静态文件），零第三方运行时依赖
- 线上地址：`http://<服务器IP>/`（nginx 80 端口托管）

> 🤖 **AI Agent / 接手开发者请先读 [AGENTS.md](./AGENTS.md)** —— 项目完整交接记忆：架构与数据流、配置规格、探测与设置 API 细节、部署链路、**踩坑记录**、设计决策史与常见任务配方。

## 服务管理（systemd 开机自启）

项目已配置为**开机自启**，由以下 systemd 单元组成：

| 单元 | 作用 |
|---|---|
| `my-homepage-settings.service` | 首页设置面板的后端 API（127.0.0.1:8300） |
| `my-homepage-probe-quick.timer` | 每 3 分钟探测端口 / 运行状态（不 fetch git，约 0.3 秒） |
| `my-homepage-probe.timer` | 每 5 分钟完整探测，含 git fetch（约 6 秒） |

手动控制脚本（需 root）：

```bash
./scripts/start.sh      # 启用开机自启并立即启动，随后跑一次探测
./scripts/restart.sh    # 重启全部服务（不改变自启状态）并立即探测一次
./scripts/stop.sh       # 停止并取消开机自启 = 永久关闭（重启服务器也不会起来）
```

> **stop 是永久关闭**：执行 `systemctl disable --now`，重启服务器后不会自启；恢复请执行 `start.sh`。
> 主页是静态文件、由共享 nginx（80 端口）托管，因此 stop 后**页面仍能打开**，但数据不再更新、设置面板保存会失败（API 返回 502）。nginx 还承载其他历史代理路径，脚本不会去停它。
> 若在「永久关闭」状态下执行 `restart.sh`，服务会临时运行，并在输出中提示重启服务器后仍不会自启。

## 如何新增一个应用

**不需要登记**——应用清单由统一探测自动发现：

1. 把应用放到对应服务器的**探测目录**下（每台服务器的探测目录在「监控中心 → ⚙ 设置 → 对应主机 → 应用探测目录」配置，默认本机与阿里云为 `/root/applications`）并启动；
2. 下一轮探测（≤3 分钟，或点「立刻同步」）自动发现，**应用中心与监控中心同时出现并纳入监控**，标「待补充」；
3. 在设置页点击该应用补充名称/简介/图标/GitHub 等展示信息；不想展示可勾选「在前端隐藏」（后端照常探测与监控）。

> 探测目录自身含 `.git` / `package.json` 等应用标记时视为单一应用（如 netwatch 的 `/root/network-monitor`）；否则每个一级子目录 = 一个应用。
> 技术栈（`languages` / `frontend` / `backend`）通常不用手写：本机应用由探测器自动识别；需要修正时在设置页填写即可。

## 端口探测原理（统一目录自动发现）

`scripts/probe-apps.mjs` 是应用中心与监控中心**唯一**的应用探测来源。每台服务器在 `scripts/monitor.config.json` 的 `hosts[].appRoot` 配置探测目录：

- **本机**：`readdir` 扫描目录 + 解析 `ss -tlnp` 所有 TCP LISTEN 端口，读取各监听进程的 `/proc/<pid>/cwd`（cmdline 兜底），进程工作目录落在应用目录内即认定端口归属；进程匹配不到时退回探测 `expectedPort` 的 TCP 连通性。`expectedPort` 正在监听且不归属其他应用时优先作为主端口（避免项目目录内附属进程，如监控网关 8301，被误判为应用入口）。
- **外机 / 公网**：每台一次 SSH 执行只读脚本（目录发现 + `ss -tlnp` + 全量进程 cwd + 逐目录 git fetch/status），与远程 git 检查同一条连接跑完；瞬态失败自动退避重试。
- **注解合并**：`scripts/apps.config.json` 只提供展示注解（名称/简介/图标/形式/技术栈/GitHub/隐藏），按目录匹配合并进发现结果；`"hidden": true` 让应用不在前端展示（后端照常探测）。
- 结果写入 `public/apps.json` 与线上 `/root/applications/my-homepage/www/apps.json`（含实际端口、附加端口、是否对外监听、运行状态、git 同步与探测时间），监控中心据此自动跟踪各主机目录。

定时器安装（root）：

```bash
cp systemd/my-homepage-probe{,-quick}.{service,timer} /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now my-homepage-probe.timer my-homepage-probe-quick.timer
```

## 设置页面（免改配置文件）

顶栏 ⚙ 按钮打开设置面板，可直接修改并保存：

- **页面信息**：站点名称（顶栏 + 浏览器标题）、首页主/副标题；
- **应用清单（盘点驱动）**：本机 / 外机 / 公网三个区块由统一探测结果自动生成，条目不可增删——新应用随探测自动出现（两中心同时展示并纳入监控），点击条目编辑展示信息（名称/简介/图标/形式/技术栈/GitHub/访问地址/期望端口）；
- **前端隐藏**：任一应用可勾选「在前端隐藏（后端继续探测）」，监控设置的主机编辑弹窗里也有同一开关（`POST /api/appmeta`）；隐藏只影响展示，探测与监控照常；

保存后自动写入 `scripts/apps.config.json`（原文件备份为 `.bak`）并**立即重跑一次探测**，几秒内页面生效，无需登录服务器。本机应用的「期望端口」旁会显示当前**探测到的实际端口**；两者不一致时点「采用」可一键写回配置。

实现：`scripts/settings-server.mjs`（零依赖 Node，仅监听 `127.0.0.1:8300`，nginx 将 `/api/` 反代到它），由 `my-homepage-settings.service` 常驻；服务端只做配置文件的校验与原子写入（不执行 shell、不触碰应用目录）。注意：该接口对局域网开放（与各应用自身「无登录」的信任级别一致），如需收紧可在 nginx 层加访问控制。

## 立刻同步

工具栏右侧的「立刻同步」按钮会调用 `POST /api/probe`，在后台立即执行一次**完整探测**（端口 + git fetch + 远程健康接口）。探测期间按钮显示「同步中…」并禁用，完成后页面自动刷新。它与完整定时探测共用同一个脚本，会并发 fetch 各仓库，通常约 6 秒完成。

页脚「最后探测」固定按**北京时间**显示，取的是探测**完成**时刻（不是开始时刻）。

## 远程应用探查（外机 / 公网）

外机与公网应用由统一探测器经 **SSH** 在目标机上自动发现（与发现脚本同一条连接完成 git 检查），无需健康接口：

- **发现**：扫描该主机 `hosts[].appRoot`（每个子目录一个应用；目录自身含应用标记则视为单一应用），要求密钥认证；
- **运行判定**：应用目录内有存活进程（cwd 命中）或归属监听端口；对外入口常由 nginx 托管——注解里配置的「访问页面 URL」端口会作为期望端口锚定（否则可能显示仅本机的后端端口）；
- **git 检查**：每个发现的远程应用目录自动 fetch + 工作区 + 未推送/未拉取检查；**公网服务器视为线上机**：仅允许 pull，同步列按线上口径显示——「线上已同步」（绿）/「线上已改」（红，线上禁止改代码）/「线上提交未推送」（红）/「可拉取」（橙，待部署）；探测对任何机器只执行只读 git 命令与 fetch，绝不 push；
- **归属**：外机 / 公网由监控主机的分组（内网 / 公网）决定，主机卡与设置面板自动分组。

## 源码同步检测（git）

探测器对每个应用目录（含自动发现的）执行 git 检查，结果随 `apps.json` 的 `git` 字段下发：

1. **fetch 校准**：默认**并发 6 个仓库**执行（可用 `PROBE_FETCH_CONCURRENCY` 调整），只 fetch 当前分支所属远端（通常是 `origin`）、不拉 tags，SSH BatchMode + 连接复用，单仓 20s 超时；保证 ahead/behind 基于最新远端快照。网络不通时回退上次快照并在悬停提示中标注「远端不可达」。手动运行 `node scripts/probe-apps.mjs --no-fetch` 可跳过网络步骤；
2. **工作区核对**：`git status --porcelain` 统计未提交（已跟踪文件改动）与未跟踪文件数；
3. **推送核对**：`git rev-list --left-right --count @{upstream}...HEAD`（无分支上游时退回 `origin/HEAD`）得出未推送（ahead）/ 未拉取（behind）提交数。

状态含义（即主页「同步」列的 chip）：

| 状态 | 含义 |
| --- | --- |
| ✅ 已同步 | 工作区干净且与远端一致 |
| 🔴 未提交 N | 有 N 个已跟踪文件的修改未 commit（源码未进 git） |
| 🟠 未推送 N | 本地有 N 个 commit 未 push |
| 🟠 未拉取 N | 远端有 N 个新 commit 未 pull |
| 🟠 未跟踪 N | 有 N 个未加入版本控制的文件 |
| ⚪ 无 Git 仓库 / 未关联远端 / 检查失败 | 无法核对，悬停可见原因 |

**离线应用**（纯 APP / 小程序 / 电视 / CLI，无 Web 服务）：`kinds` 不含 `web`（如 `["app"]`）时，主页状态显示灰色「**离线应用**」，不做端口探测、不产生访问链接。只要 `kinds` 含 `web`，即使同时是 APP 也会正常探测 Web 端口。此类应用仍参与 git 同步检查（有仓库时）。

主页顶部统计条实时汇总「N 个源码未同步」；配置里没填 `github` 但仓库有 `remote.origin.url` 的应用会自动生成 GitHub 链接兜底。

## 应用形式、技术栈与部署位置

每条应用可配置以下信息，均在首页展示、可在设置面板修改：

- **应用形式** `kinds`：`web`（Web）、`app`（APP）、`miniapp`（小程序）、`tv`（电视）、`cli`（CLI），**可多选**。首页显示为灰色 chip。是否探测由它决定：含 `web` 就探测，不含则视为离线应用。
- **技术栈**：`languages`（主要语言）、`frontend`（前端框架）、`backend`（后端框架），均为数组。本机应用由探测器从 `package.json` / `requirements.txt` / `pyproject.toml` / `go.mod` / `build.gradle` / `app.json` / README 等自动识别；设置页可手动覆盖。远程应用不在本机目录，需在设置页手动填写。
- **业务标签** `tags`：仍可在设置页维护，但当前不在首页表格/卡片展示。
- **部署位置** `env`：本机应用固定显示「本机」（蓝色）；`remoteApps` 中 `lan` 显示「外机」（绿色，局域网其他主机），`public` 显示「公网」（橙色，云服务器）。
- **HTTPS** `https`：本机应用可在设置面板勾选「使用 HTTPS」，首页访问链接会拼成 `https://<当前主机名>:<端口>`；配置对应 `"https": true`，缺省为 `false`（http）。远程应用直接使用配置的 `url`，不需要该字段。

配置缺省时自动推断：旧字段 `type: "app"` 的条目默认 `["app"]`，其余默认 `["web"]`；部署位置按所在区块推断。技术栈字段留空时显示自动识别结果，手动填写后以手动值为准。例如既有网页又有 APK 的应用可同时勾选 Web 与 APP，仍会探测 Web；电视/CLI 不勾 Web 时按离线应用处理。

自动识别是启发式的：它能覆盖当前这些项目，但新增应用若目录结构特殊，结果可能在设置页修正。识别不到的项显示「无」。

## 运行状态

| 状态 | 颜色 | 判定 |
| --- | --- | --- |
| 运行中 | 绿 | 端口正在监听；远程应用的健康接口正常 |
| 未运行 | 红 | 端口未监听；远程应用的健康接口不可达 |
| 离线应用 | 灰 | `kinds` 不含 `web` 的纯 APP / 小程序，不做探测 |

离线应用不会发起端口探测，也不显示访问链接；远程应用同样统一使用「运行中 / 未运行」文案。

## 排序

### 手动排序（默认顺序）

排序下拉选「手动 / 默认顺序」时可直接排列应用：

- **表格视图**：按住行首的 ⠿ 手柄拖拽到目标位置；
- **卡片视图**：卡片右上角 ↑ / ↓ 按钮上下移动，或直接拖拽卡片；
- 手动顺序**保存在服务端**（写入 `scripts/apps.config.json` 的 `order` 字段），**对所有浏览器、所有前端页面一致生效**：任意一台设备上排好序，其他浏览器约一个探测周期内自动跟随；新发现的应用自动排在最后；工具栏出现 ↺ 按钮可一键清除、恢复默认（同样全局生效）。

也可以手工编辑 `scripts/apps.config.json` 顶层 `"order": ["study-log", "cloud-monitor", …]`（id 数组）后跑一次 `npm run probe`，效果相同；未列出的应用按原相对顺序排在后面。

### 自动排序

- **表格视图**：点击「状态 / 应用 / 访问地址 / 同步」表头排序，再次点击同一表头切换正反方向（表头高亮 + ▲/▼ 指示）；
- **卡片视图**：使用工具栏的「排序」下拉（两种视图共用同一排序状态），旁边的 ↑/↓ 按钮切换方向；
- 排序规则：名称按中文拼音；端口升序（未监听的排最后）；运行状态按「运行中 → 未运行 → 离线应用」；同步状态按问题严重度排序（未提交 → 无仓库 → 未推送 → 未拉取 → 未跟踪 → 检查失败 → 未关联远端 → 已同步）。

自动排序时隐藏拖拽手柄（仅默认顺序下可手动排列）；切换回「手动 / 默认顺序」即恢复手动排列。

## nginx 配置（80 端口）

`/etc/nginx/conf.d/default.conf` 指向 `/root/applications/my-homepage/www`（`listen 80 default_server`，SPA 回退 + gzip + 静态资源缓存）。原配置备份于 `/etc/nginx/conf.d/default.conf.bak`。

## 监控中心（主页顶栏切换）

**服务器监控看板 + Web SSH 终端**已并入主站：顶栏「我的应用 / 监控中心」两个标题点击即切（同一页面，无需跳转；`#monitor` 直达，选择会被记住）：

- **多机纳管**：本机直读 `/proc`（5s），远程主机经 SSH 免 Agent 采集（20s），内网蓝 / 公网橙分组卡片 + CPU/内存/磁盘仪表环；主机卡核数、内存、硬盘按实际可用核数、标称内存与整盘原始容量展示。
- **双向同步**：监控设置的主机编辑弹窗可勾选「**同步到应用中心**」，自动在应用中心维护同名远程应用（健康接口默认 `http://地址/`，可在应用设置修改）；与应用中心的「同步到监控中心」互为反向，勾选后主机/应用信息变更自动跟随，同步中断自动退避重试，取消勾选不会删除已创建的条目。
- **应用资源占比与目录跟踪**：按目录归属聚合进程资源（cwd/exe/cmdline/cgroup 四路匹配），主页登记应用的目录自动纳入跟踪，无需重复配置；点击卡片内联展开详情——CPU/内存/网络/磁盘 IO 趋势、分区用量、目录占比（内存/CPU/IO/线程/句柄维度）、多目录历史对比（1 小时 / 24 小时 / 7 天）与进程明细下钻。
- **Web 终端**：卡片点「终端」侧边抽屉进入目标机网页 SSH（xterm.js + ssh2，同一会话鉴权），可弹出独立窗口；最多 **6 个终端窗格**（同一主机可多开，3 列排布，多端输入可广播；关闭抽屉仅隐藏保留现场，✕ 关闭需确认清空）；空闲 8 小时 / 单会话 12 小时硬顶 / 每主机并发 10 上限，会话与命令入审计日志。
- **告警**：CPU/内存/磁盘/负载阈值持续 3 分钟触发（可在设置调整），hero 区横幅展示，支持 webhook 通知。
- **安全**：独立访问密码（scrypt 存储）构成**全站登录门**——未登录时登录层覆盖应用与监控两个视图，本浏览器登录一次长期免密（会话持久化、重启不掉线）；网关宕机自动放行不锁主页。远程凭据推荐密钥认证，密码凭据 AES-256-GCM 加密存储。

架构与选型见 `docs/monitor-terminal-blueprint.md`，部署/配置/排障见 `docs/monitor-ops.md`。网关服务 `my-homepage-monitor.service`（`scripts/monitor-server.mjs`，仅回环 8301），已纳入 `scripts/start.sh / restart.sh / stop.sh` 管理。

## 设计对比端点 /unslop/

`/unslop/` 是主站首页的**净化对比版**：视觉与 `/` 完全同款（同一套配色、chips、emoji 图标与布局 1:1），仅做了几处不改变观感的优化（表头去大写、`transition: all` 收敛、h1 字重、键盘焦点环、动效降级）。它与主站读取同一份 `apps.json`，功能一致（表格/卡片、排序、手动拖拽、立刻同步、深浅主题）。纯 HTML/CSS/JS 静态页（`unslop/` 目录，不参与 Vite 构建），改完刷新即生效；设置入口链接回主站面板。旧主页 `/` 完全不受影响。

## 毛玻璃 v2 对比端点 /glass-v2/

`/glass-v2/` 是**应用导航 + 监控中心双视图**的毛玻璃对比版（2026-11-10，unslop skill 产出）：暗色科技蓝为主（浅色玻璃可切）、悬浮玻璃顶栏双标题、极光光斑底、玻璃表格/卡片/仪表环/图表盒、呼吸状态点、xterm 玻璃终端抽屉。功能与主站 SPA 对齐（排序/拖拽/同步/监控详情/设置/终端），会话 Cookie 与主站共享——主站登录过此处自动免密。纯静态零构建（`glass-v2/` 目录），改完刷新即生效。旧的 `/glass/`（旧首页毛玻璃版）保留不动。
